# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm install`: install dependencies. Node.js `>=22.18.0` is required: Node runs the server's TypeScript directly and provides its SQLite database.
- `npm run dev`: the game with hot reload (http://localhost:5173). It forwards `/api` requests to port 3000, so run `npm run server` in a second terminal to play online. Without the server, only "Jouer sans compte" works.
- `npm run server`: the game server on port 3000, restarting on code changes. Its database is `data/royaume.db`, which git ignores.
- `npm start`: production server, with the API plus the built game from `dist/` (run `npm run build` first). Environment variables: `PORT`, `DATABASE_FILE`, `STATIC_DIR`.
- `npm test`: run the tests once (Vitest), covering the game rules and the server. `npm run test:watch` re-runs them on save.
- `npx vitest run server/app.test.ts -t "<test name>"`: run a single test.
- `npm run simulation` (or `npm run simulation -- orcs 7` for another race and seed): a virtual player (`scripts/simulation.ts`) follows the objective chain from a new game and prints the game time each objective takes, or where it gets stuck. Run it after balancing changes in `config.ts`; it depends on balancing values, so it is not a test.
- `npm run build`: type-check (`npm run typecheck`: `vue-tsc` for the client, `tsc -p tsconfig.server.json` for the server, the rules and `scripts/`), then build the game into `dist/`. There is no linter yet.

npm 10 can crash with `Cannot read properties of null (reading 'edgesOut')` when it resolves the dev dependencies from scratch (vitest's optional peers), for example when adding a package. `npm install --legacy-peer-deps` works around it. Installing from the existing `package-lock.json` is unaffected.

## Architecture

A Vue 3 + TypeScript + Vite single-page app with a French UI, plus a Node.js server (Hono and SQLite) that holds player accounts and their games. Roadmap steps 1 and 2 are implemented: the city, troops, heroes and research, and a live map of the surroundings where the player commands armies, fights timed battles against monster camps and patrolling monster bands, and gathers resources. Monster raids march on the city, which its troops and the Remparts defend. Both maps (the city and its surroundings) can be panned and zoomed. Step 3 is under way: accounts and online games work. For now the owner develops with a local server; hosting comes later.

- `src/game/` holds the game rules in plain TypeScript, with no Vue, DOM or browser-storage dependency. Both the browser and the server run this code, so keep it that way. Node runs these files directly by stripping their types. Imports inside `src/game/` and `server/` therefore keep their `.ts` extension, and only erasable TypeScript is allowed: no `enum`, no parameter properties (`tsconfig.server.json` enforces this).
  - `config.ts` holds every number: resources, races and their bonuses, buildings (the Entrepôt sets the reserves' room: `STORAGE_BASE`, `STORAGE_GROWTH`; the Hôpital's beds and the wounded: `WOUNDED_SHARE`, `HOSPITAL_BEDS_*`, `HEAL_COST_SHARE`, `HEAL_TIME_SHARE`), troops (the four `Family` units plus one unit per race, with its `family` and `race`, and what each one carries, `load`), heroes (`HEROES`: recruitment, skills and their `SkillEffect`, the XP curve), monsters (including the XP each one gives) and camps, quests (`QUESTS`: goals, rewards, and an optional `gift` such as the dragon egg), the dragon (`DRAGON_*`: hatching cost and time, attack, health and growth, XP curve, rest, upkeep), spells (`SPELLS`: effect, Tour des mages level, cost, duration of tens of minutes, `absence` for the defence spells that last a night, and `rechargeSeconds` for the one that must re-form before it can be cast again), monster bands (kinds, growth per level, levels by distance, aggro radius, spawn timing, patrols, and chases: `BAND_SIGHT_FACTOR`, `CHASE_SPEED`, `CHASE_LEASH`), raids and the city's defence (`RAID_*`: start, interval, speed, size, gates, plunder, respite; `WALL_*`: guards and health bonus; `PROTECTED_PER_CASTLE_LEVEL`, `SIEGE_*`), resource nodes (`NODE_KINDS`: amounts, gather rates, spawn timing), costs, durations, production, growth factors and the starting state. It also holds the world map geometry (`WORLD`, camp positions, `BAND_SPOTS`, `NODE_SPOTS`, `RAID_GATES`, and the relief: `ENCAMPMENT`, the great encampment's cirque in a north-south mountain barrier, whose massifs `MOUNTAINS` and `ENCAMPMENT_GATE` are generated with integer coordinates, its bands `ENCAMPMENT_BANDS`, its watchtower's `WATCH_RADIUS`, and its hidden `ENCAMPMENT_TRAPS` with `TRAP_RADIUS` and `TRAP_DAMAGE`) and the pace of the world (`MARCH_SPEED`, `PATROL_SPEED`, `RAID_SPEED`, `WORLD_TICK_SECONDS`, `BATTLE_ROUND_SECONDS`), because the rules move armies and bands on the map. Melee numbers live there too: `MAX_ATTACKERS`, `SIDE_ATTACK_BONUS`, `REAR_ATTACK_BONUS`, `ENCIRCLED_SIDES`, `ENCIRCLED_ATTACK_MALUS`. Balancing changes go here, not in the rules.
  - `rules.ts` is pure functions over an immutable `GameState`. The reserves hold `storageCapacity(state)` of each resource (the Entrepôt, plus the Intendance tech's `storage` effect): `accrue` stops a resource's production at that room, without taking away what is already above it, while upkeep still drains it; loot, gathering, quest rewards and siege loot are never capped. `checkCost(resources, cost, capacity)` names a cost the room cannot hold (« agrandis l’Entrepôt »), which `checkPay` uses for buildings, research, spells, heroes and the dragon's hatching (not training, whose batches can shrink). When food is empty and upkeep exceeds production, troops are starving (`isStarving`): nobody deserts, but battle rounds played while starving apply `STARVATION_ATTACK_MALUS` to the attackers. `constructions` holds up to `maxConstructions` builds (one, then two from `SECOND_CONSTRUCTION_CASTLE_LEVEL`), never two on the same building (`constructionOf`). `trainings` holds at most one training per troop type, so the types train in parallel; a race unit can only be trained by its race (`checkTraining`). Research effects are data in `TECHS` (`TechEffect` kinds) and are read through `techBonus(state, kind, resource?)`, which production, durations, battles, march speed and army slots all use. Players can dismiss troops (`dismissTroops`) to cut upkeep, which also avoids a soft-lock (no food means no Château upgrade, which caps the farms). Each player action (`startUpgrade`, `startResearch`, `startTraining`, `recruitHero`, `learnSkill`, `claimQuest`, `castSpell`, `startMarch`, `orderArmy`, `dismissTroops`) advances first, then validates with its `check*` function, which returns the reason shown in the UI (a cost that cannot be paid names what is missing: `checkCost`).
    - Time: nothing runs in the background. `advance(state, now)` replays everything up to `now` in time order, accruing net production (production minus troop food upkeep, never below zero) up to each step. Scheduled events happen at their exact time (`nextEvent`: construction, research, training and spell ends, band, node and raid spawns, raid arrivals). While something can happen outside the city, the world also moves in ticks (`worldTick`, one per `WORLD_TICK_SECONDS`): due battle rounds are played, armies march (and may spring a trap), gather or arrive, chasing bands move (`stepChases`), bands attack the armies they reach (`checkAggro`), then spot new ones (`spotArmies`). Ticks fall on absolute multiples of the tick length (`tickedAt` holds the last one), and an event at the same instant comes first, so advancing in one jump or second by second gives the same result (a test checks it). This is what makes offline progress work. When nothing can happen (`worldIsQuiet`: no battle, no band chasing or walking back, and either no army outside or every army idle where no band can ever see or reach it, `threatens`, with no raid on the map), there are no ticks, so a week offline stays cheap. For a patrol, `patrolSees` tries points of its loop every few units, so an army idle behind a mountain does not keep the world ticking. `advance` throws after 10 000 steps at the same instant, or on an event time that is not a number, rather than loop forever.
    - Armies: `state.armies` holds the armies outside the city (`FieldArmy`: troops, position, `order`, `status`, `load`, `fought`, `escaped`), up to `maxArmies` (1 + the Commandement tech). `startMarch` sends a new army out of the city with a first order, and `orderArmy` gives an army a new one at any time (it retreats first if it is fighting, but `checkOrder` refuses to send it against the foe it is already fighting). An order is a `Target`: a point, a camp, a band or a resource node (by id), or the city. Armies march in straight lines at `marchSpeed`. At a point, they wait (`idle`); at a camp or a band, they fight; at a node, they gather; at the city, they disband and add their `load` to the reserves.
    - Heroes: `state.heroes` holds the recruited heroes (`Hero`: level, xp, skill levels). A hero leads at most one army (`FieldArmy.hero`, `heroArmy`) and is free again when the army disbands or falls. `heroBonus(state, hero, kind, family?)` sums its skill effects, which apply to that army only: attack and family attack in `battleStacks`, health in the battle's `healthFactor`, march speed (`marchSpeed(state, hero)`, `marchDuration`), gathering (`gatherRate`) and load (`carryCapacity`). `endBattle` gives the hero XP for each monster defeated, whatever the outcome (`gainXp`, `xpToNextLevel`); each level brings a skill point (`skillPoints`).
    - Spells: `state.spells` holds the spells at work, each until its `endsAt`, when a scheduled event removes it (so production changes at the exact time). `spellBonus(state, kind, resource?)` adds their effects to production (`buildingOutput`), attack (`allyStacks`), health (at battle start), march speed, and the city's defenders' health in sieges (`siegeHealth`, in `cityFighter`). A `noRaids` spell (the Brume d'oubli) hides the city: while it works (`raidsHeldUntil`), `spawnRaid` moves `nextRaidAt` to its end, so the held raid sets out when it lifts (the spell's end comes first at the same instant); raids already marching still arrive. The Tour des mages level unlocks them, and a spell cannot be cast again while it works, nor, for a spell with `rechargeSeconds` (the Brume), before `state.spellsReadyAt` (its end plus the recharge, set by `castSpell`; `checkCast`).
    - Hospital: `state.wounded` holds the wounded waiting at the Hôpital, and `state.healing` the one group being healed (`Healing`; a scheduled event gives it back to `troops`). Whenever troops fall (`leave`, `leaveCity`, `springTrap`), `woundFallen` sends `WOUNDED_SHARE` of them (rounded up) to the hospital within its `freeBeds` (`hospitalBeds`: none without the Hôpital; short beds are shared by `apportion`); the others die. Reports list them in `wounded`, a part of `lost`. The wounded neither eat nor fight. `checkHealing` and `startHealing` heal a chosen group for `healingCost` (`HEAL_COST_SHARE` of their training cost) over `healingDuration` (`HEAL_TIME_SHARE` of their training time).
    - Quests: `QUESTS` form a chain. `currentQuest` is the first one not yet claimed (`state.quests` lists the claimed ones), and only it can be claimed, once `questDone` (`checkClaim`, `claimQuest`). `questProgress` reads each goal from the state; what the state cannot recompute is counted in `state.stats` (victories, bands defeated, raids repelled and victories per camp, `campsDefeated`, in `endBattle` and `endSiege`, resources gathered in `gather`).
    - Camps: a defeated camp stays empty for `CAMP_RESPAWN_SECONDS` (`state.campsCleared` holds when its monsters come back, `campEmptyUntil`): it cannot be targeted meanwhile, and an army that reaches it after another army emptied it just waits there.
    - Trial mode: `state.trial` (toggled by the `trial` action, which `parseAction` never accepts, so only games without an account have it) multiplies the player's attack and health by `TRIAL_BOOST` (`trialBoost`, in `battleStacks` and the battles' `healthFactor`), to test alone what will need several players.
    - Battles are melees. `state.battles` holds them (`Battle`: `round`, `allies` and `foes`), with one round every `BATTLE_ROUND_SECONDS`. A fighter has a `ref` (`army:12`, `city`, `band:34`, `camp:wolfDen`), a `target` (one fighter of the other side, or null while it waits for room), a `slot` (0 to 7: the direction where it stands, seen from its target, so it faces the opposite way) and its `start` health. `AllyFighter` is one of your armies or the city in a siege (`army` null): its `sent` troops, `health`, `healthFactor`, `siege` guards, `dragon`, its own `rounds` log, the foes it `met`, and its share of `loot`. `FoeFighter` is a band or a camp: `foe`, `enemies`, `health`, and `damageBy` (damage taken from each ally, to share its loot). `engage(state, attacker, target, at, ambush)` starts a melee, or joins the target's melee: the attacker takes the free slot nearest to the side it comes from (`directionOf`, `approachFrom`; no trigonometry, so every engine agrees; a raid comes from its gate), at most `MAX_ATTACKERS` around a target (`freeSlot`); with no room it waits and the state is unchanged. A target that strikes nobody turns to its attacker. `playRound` lets every fighter strike its target at once (`allyStacks`, `foeStacks`, `strike`), with `flankBonus` from its place (`relativeSlot`, `flankOf`: front, side, rear) and `ENCIRCLED_ATTACK_MALUS` when the striker is itself `encircled` (struck from `ENCIRCLED_SIDES` sides); the city has no flanks and is never encircled. Each strike takes at most `1 / MIN_BATTLE_ROUNDS` of the target's `start` health (`roundCap`), so a duel lasts at least `MIN_BATTLE_ROUNDS` rounds and a swarm kills fast. A foe's losses are credited to its strikers by damage (`apportion`), in each ally's round log (`flank`, `attackers`, `encircled`). `settleRound` then removes the fallen: a foe that falls (`foeFalls`) shares its loot by `damageBy`, counts in the stats, and disappears (a band) or empties its camp; the keeper's key goes to the army that struck it hardest. When every foe has fallen, every ally wins, even one that fell in the same round; an ally whose troops have all fallen loses (outside the city the dragon never fights alone); after `MAX_BATTLE_ROUNDS`, everyone leaves in a `draw`; otherwise fighters whose target left pick another (`retarget`: one of their attackers first, else the nearest opponent with room). `leave` writes an ally's `BattleReport` (`foe`, the first foe met, and `foes`, all of them; `outcome`, `ambush`, its `rounds`, `enemyLost` from its own kills, and the hero's `HeroGain` from them) and gives the army what its survivors can carry of its loot share (`fitLoad`). An army attacked on the way then resumes its order; otherwise it waits where it stands. When no ally remains, `closeBattle` sends the bands back to their round (or march). `orderArmy` turns a fighting army toward another foe of its melee (`switchTarget`, `checkOrder` refusing its current target or a crowded one), or makes it retreat (`leave` with `retreat`, then `afterLeave`). A trap's report has `foe: { type: 'trap' }`.
    - Bands: `state.bands` patrol an octagon loop (`patrolLoop`, `PATROL_RADIUS`) around their `home`. `bandPosition` derives a band's position from `phase`, `since` (null while it is off its loop: fighting or chasing) and `direction`, so a patrolling band needs no per-tick state; a chasing band is at `chase.position`. Whether a band fights is read from the battles (`bandFighting`, `bandBattle`), not from `since`. `checkAggro` makes a band engage any army within its `aggroRadius` (an ambush), joining the army's melee if it already fights, unless the band is in the army's `fought` list; the army that marched on that band engages it itself. Bands spawn as scheduled events (`nextBandAt`, `null` when the map is full) on free `BAND_SPOTS`, never within reach of an army. The spot, the level (from distance, sometimes one more), the kind, the starting phase and the direction are drawn with `random(state.seed)`. That generator is seeded from the state, so the browser, the server and replays all agree.
    - Chases: a patrolling band (`canChase`: not a raid, not a still chief) sees `sightRadius` (its aggro radius times `BAND_SIGHT_FACTOR`) when there is no mountain in between. `spotArmies` makes it leave its loop for the nearest army it sees, even one already fighting (it will join the melee) (`Band.chase`: the army, and the band's position; its `phase` is frozen, `since` null) unless the army already fought it or escaped it. `stepChases` moves it each tick at `CHASE_SPEED` along `routeBetween` toward the army; within aggro range and in sight it stops, so `checkAggro` starts the battle (or it waits there while the army fights another one). It gives up (`giveUp`) when it gets more than `CHASE_LEASH` from its `home`, when no route reaches the army (the army then lists it in `FieldArmy.escaped`: it never chases that army again, but still ambushes it on contact), or when the army is gone. It then walks back (`chase.army` null) to the loop point where it left and resumes its round (`since` set again); after a battle, a band that had chased does the same. `bandsNearPath` and `spawnBand` use the sight radius for patrols.
    - Raids: a raid is a `Band` with `raid: true`. It walks from its `home` (one of `RAID_GATES`, drawn at random) straight to the city at `RAID_SPEED`, so `phase` is the distance walked and `raidArrival` gives its arrival time, a scheduled event. Raids do not count towards `MAX_BANDS` (`patrolCount`) and free no band spot when they go. `nextRaidAt` is null until a Château upgrade reaching `RAID_CASTLE_LEVEL` completes (`finishConstruction`), then `spawnRaid` schedules the next one every `RAID_INTERVAL_SECONDS`; the raid level follows the Château (`raidLevel`), with `raidMonsters` and `raidLoot` scaled by `RAID_SIZE`. Armies can target or meet a raid like any band (an interception counts in `raidsRepelled`). At the city, `startSiege` makes the raid engage the city (`cityFighter`: the city's troops with `WALL_HEALTH_PER_LEVEL` more health, a `siege` with the wall guards, `wallGuards`, as one more stack after the troops, and the dragon if it is home). A raid arriving during a siege (`siegeOf`) joins it; only when `MAX_ATTACKERS` raids surround the city does it wait `SIEGE_WAIT_SECONDS` at the gates. Armies outside can join a siege by attacking a raid. During a siege, troops can neither leave nor be dismissed. When the city leaves the melee (`leaveCity`), the siege ends: its fallen defenders go through `woundFallen` like any others, it puts its loot share into the reserves, or on a defeat lets the surviving raids take `plunderOf` together (`RAID_PLUNDER_SHARE` above `protectedAmount`, capped by what their monsters carry) and pushes `nextRaidAt` back by `RAID_RESPITE_SECONDS`; the raids still standing leave, and armies that came to help leave in a `draw`. Its report has `army: null` and a `siege` (`SiegeReport`: guards, guards lost, plunder, and `healed`, the defenders who got up at once in reports from before the hospital).
    - Dragon: `state.dragon` is null until a quest with `gift: 'dragonEgg'` is claimed, then holds the egg (`stage: 'egg'`). `hatchEgg` (needs the Aire du dragon, `dragonRoost`) pays `DRAGON_HATCH_COST` and sets `hatchAt`, a scheduled event after which the dragon is `grown`. Its `xp` grows like a hero's, and `dragonLevel` derives its level from it (`dragonXpForLevel`), never above the Aire's level; `dragonAttack` and `dragonHealth` follow. `startMarch` takes it along with `dragon: true` (`FieldArmy.dragon`, `checkDragon`: one army at a time, with at least one troop, not while it rests). In a melee, `AllyFighter.dragon` (`battleDragon`: attack, starting and current health) is one more stack after the wall guards, with the army's attack bonuses and health factor; at home, it also defends the city in sieges (`dragonAtHome`). `dragonAfterBattle` gives it the same XP as a hero; if it fell (`BattleRound.dragonFell`), or was left alone when its whole escort fell, it leaves the army and rests until `restUntil` (`dragonResting`); in a siege it fights to the end. It eats `DRAGON_UPKEEP_PER_LEVEL` per level in `upkeepPerHour`. Reports carry its `DragonGain`.
    - Resource nodes: `state.nodes` (`ResourceNode`: resource, level, position, `remaining`) spawn the same way (`nextNodeAt`, `NODE_SPOTS`). Only one army at a time can gather a node (`nodeGatherer`). Each troop gathers its resource's `gatherRate` per second. The army heads home by itself when it is full (`carryCapacity`, from each unit's `load`) or when the node runs out, and an empty node disappears.
    - Relief: armies never cross `MOUNTAINS`, nor the great encampment's gate while it is closed (`obstaclesFrom`; an army beyond the gate can always come back). `routeBetween` gives an army's route around them, which `stepArmy` follows and `marchDuration` and `bandsNearPath` measure; `checkTarget` refuses a point inside the mountains and a target no route reaches. A band neither spots, ambushes nor is attacked across a mountain (`inSight`). Bands and nodes only spawn where an army from the city can go (`reachableFromCity`), so they do not fill the region beyond the gate.
    - Great encampment: its bands (`ENCAMPMENT_BANDS`: five patrols, the key keeper, two elite guards, the Seigneur des Crocs and the watchtower) are ordinary bands with `encampment: true` (they never count toward `MAX_BANDS` nor free a band spot), the chiefs and the tower `still` (`bandPosition` keeps them at home, with no patrol loop). While the tower stands (`watchtower`), every army it sees within `WATCH_RADIUS` (`towerSees`) alerts the encampment's patrols: `spotArmies` sends them after it, even while it fights. Hidden traps (`ENCAMPMENT_TRAPS`) spring when a marching army passes within `TRAP_RADIUS` (`springTrap`, in `stepArmy`, before it arrives): `TRAP_DAMAGE` is spread over its troops by head count against their health (`armyHealthFactor`: Armures, hero, spells, trial), the load is cut to what survivors carry, a report with `foe: { type: 'trap' }` is written, and the trap stays sprung (`state.encampment.sprung`) until the reset; an army wiped out disappears (its key returns, a dragon with it goes home to rest). `resetEncampment`, a scheduled event every `CAMP_RESPAWN_SECONDS` (`state.encampment.resetAt`, null for no encampment, as in `richGame`), puts them all back (but lets a band in battle finish it), closes the gate, re-arms the traps and takes the key back. Beating the keeper gives the key to the winning army (`FieldArmy.key`); the army opens the gate (`state.encampment.gateOpen`, so `obstaclesFrom` drops it) when it comes within `GATE_REACH` of `ENCAMPMENT_GATE_FRONT` (`openGate`, each world tick). A lost key (its army destroyed, or back in the city) returns to its keeper (`returnKey`).
    - Helpers: `targetPosition` takes a time, because bands move. `bandsNearPath` lists the patrols near a path, for warnings, and `patrolDistance` gives the exact closest distance between a patrol and a point. `distance` uses `Math.sqrt`, not `Math.hypot`, whose results can differ between JavaScript engines.
  - `terrain.ts` is the geometry of the relief, with no game rules: polygons, `clear` (a straight line crosses no mountain), `insideAny`, and `findRoute`, the shortest route around them (a visibility graph between the mountains' outer corners, cached per array of polygons, never leaving the map) that armies follow with `walk`.
  - `actions.ts` turns player orders into data (`Action`: upgrade, research, train, dismiss, heal, recruit, skill, claim, cast, hatch, march with an optional hero and dragon, order). `performAction(state, action, now)` advances, checks and applies an order, and returns the refusal reason if it is impossible. `parseAction` validates untrusted JSON (known ids, integer counts, targets inside the map, no other fields) before the server uses it.
  - `save.ts`: `restoreState` rebuilds a stored game field by field, defaulting what older saves lack and dropping fields the game no longer has. It refuses (returns null) a damaged game whose times, positions or counts are not numbers (`isSound`), which would crash the game or make `advance` loop, and drops bands without monsters. An objective inserted later in the middle of the chain counts as claimed when a later one is (`questChain`). The browser save and the server database both go through it, so a new state field must get its default there. It also upgrades older saves: armies from before map orders (`expeditions`) come home with their troops and loot, motionless bands start patrolling around where they stood, and old reports get an `outcome`. Games from before heroes get `heroes: []`, and their armies `hero: null`. Games from before raids get `raid: false` bands, `siege: null` battles and reports, and a first raid five minutes later if their Château is already big enough. Games from before the dragon get `dragon: null`, armies `dragon: false`, battles and reports `dragon: null`, and empty `campsDefeated`. Games from before camps repopulated get empty `campsCleared` and `trial: false`. Games from before the great encampment get `encampment: { resetAt: updatedAt, gateOpen: false, sprung: [] }` (so it fills at the next advance), bands `encampment: false` and `still: false`, and armies `key: false`. Games from before chases and traps get bands `chase: null`, armies `escaped: []` and `sprung: []`. A battle from before melees (one army or the city against one foe) becomes a melee of two fighters facing each other (`upgradeBattle`), and old reports get `foes`. Armies and battles from before race units get zero counts for the new troop types. A single `construction` from older saves becomes `constructions`, and older games start with empty `stats`, no claimed quests, no spells and no recharges (`spellsReadyAt`). Games from before the hospital get no `wounded` and `healing: null`, and their reports empty `wounded`.
  - `battle.ts` is the deterministic battle simulation: damage spread across the enemy groups by head count, and a bonus against the family named in `strongAgainst`. A round deals only `BATTLE_DAMAGE_SCALE` of each fighter's attack. `strike` gives one side's blows on another (the melee uses it, one striker at a time), capped (`roundCap`: a share of the target's starting health); `fightRound` plays both directions at once with optional `caps`; both slow battles down without changing who wins. Stacks carry a `Family`: monsters, and race units (`UnitDef.family`), fight with the strengths of one of the four families. `fightRound` plays one round on health pools and returns its log (damage and losses), which the rules keep in the battle's `rounds` for the combat log; `fight` plays a whole battle at once.
  - The tests (`*.test.ts`) avoid depending on balancing values: they build states with unlimited resources, or groups with fixed stats. `richGame` has no bands, no nodes and no raids, and an Entrepôt at level `ROOMY` (100), so its room never limits production (`roomy` gives that room to any game); `withBand`, `withRaid` and `withNode` place them exactly where a test needs them, `withHospital` builds the Hôpital at a chosen level, `withHero` gives a hero chosen skills, `withDragon` a grown dragon of a chosen level, `withEncampment` fills the great encampment, `reach` fulfils any quest goal, `nearCity` and `onRoad` give positions, `placeArmy` puts the first army somewhere without a march, `allyIn` and `foeIn` give the first fighters of the first melee, and `runUntil` advances second by second until a condition holds. Comparing a game advanced in one jump with the same game advanced second by second, `expectSameGame` checks every field exactly but the resources, whose last digits depend on the order of the additions.
- `server/` is the authoritative game server. The client never sends a state, only actions, and the server applies them with the rules above.
  - `app.ts` builds the Hono app and its JSON routes, listed at the top of the file: accounts, sessions, `GET`/`POST`/`DELETE /api/game` and `POST /api/game/actions`. It also serves `dist/` with cache headers. `GET /api/game` returns the game as it was at the last visit and saves it advanced to now, so the client can build the "Bon retour" summary. A request that changes a game loads, applies and saves with no `await` in between, so concurrent requests cannot interleave. Keep it that way.
  - `auth.ts` checks names and passwords and handles tokens. Names are 3 to 20 letters, digits, spaces, hyphens or apostrophes, unique regardless of case (`nameKey`). Passwords need at least 8 characters and are stored as scrypt hashes with OWASP settings. Session tokens are random, stored only as SHA-256 hashes, sent as `Authorization: Bearer`, and expire after 30 days unused. After 10 wrong passwords for a name, `app.ts` locks that name for 15 minutes (in memory). Each attempt counts before the slow password check, so attempts sent all at once cannot slip under the lock, and only names with an account are counted, so invented names cannot fill the memory. A name already taken is refused before hashing the password, and `POST` requests must be JSON (415 otherwise), which stops other sites from making their visitors register or try passwords.
  - `db.ts` wraps `node:sqlite` with three tables: `accounts`, `sessions`, and `games` (the state as JSON). A schema change goes in a new entry at the end of `MIGRATIONS`, tracked with `PRAGMA user_version`.
  - `main.ts` starts the server from the environment variables.
  - `app.test.ts` runs the whole app in memory, with a fake clock and light scrypt settings. It sets states directly with `giveGame` instead of depending on balancing values.
- `src/ui/` is the display layer. `useGame.ts` owns the reactive state and ticks once a second.
  - A game lives either online or on the device. Online, the session is kept in `localStorage` and the server decides. Without an account, `storage.ts` saves the game under a versioned key; bump `SAVE_VERSION` on incompatible format changes. A save that cannot be restored or advanced (damaged, or from an older version) is set aside under `royaume-sauvegarde-abimee`, and the player is told and can start again instead of facing a blank page. Only one tab plays a game without an account at a time: the tab that opens it says so on a `BroadcastChannel`, and the others pause without saving (`elsewhere`, a « Jouer ici » dialog in `App.vue`). If the browser refuses to save, the player is warned once.
  - Online play: each order is applied locally right away with `performAction`, then sent to the server, whose answer replaces the state. Requests go through a queue one at a time, and only the last answer in line is applied. While the server is unreachable, new orders are refused with a notice, since the next sync would silently erase them. `api.ts` wraps `fetch` and estimates the server clock (`serverNow`), which drives the timers online. The client re-syncs every minute, when the tab becomes visible again, and every 10 seconds while the server is unreachable.
  - `away.ts` builds the "Bon retour" summary: full reserves (their production stopped), finished work (healing included), battles (naming every foe of the melee), sieges (by one raid or several, repelled or plundered, with what was taken), traps sprung, armies back home (not those whose report shows them wiped out), the wounded waiting at the Hôpital (and a full Hôpital), hero levels, the dragon's birth or new level, spells that ended (and the defence spells that watched over the city), an objective reached, new bands and nodes, and a raid marching on (or besieging) the city.
  - The resource bar (`ResourceBar`) shows each reserve's room as a thin bar under it, gilt when nearly full, and « plein » instead of the rate when its production has stopped.
  - Screens:
    - `AccountView.vue`: log in, create an account, or "Jouer sans compte".
    - `RaceChoice.vue`: pick a race.
    - `GameScreen.vue`: the game itself, a full-viewport screen designed for landscape, like a mobile game. It also works upright (the panel then sits under the map, and a chip suggests turning the phone). The map fills the screen: `CityMap` or `WorldMap`, kept alive so each keeps its pan and zoom. On top of it, a HUD: the resource bar, the current objective (one tap claims a reached objective), the raid alert (`raidAlert`: the countdown to the next raid's arrival, which opens that raid's panel, or "Cité assiégée", which opens the walls), what is in progress in the city (each chip opens its building, the dragon's hatching and the Hôpital's healing included), the armies outside (a ❗ on those a band is chasing), the city/surroundings toggle, and the Héros, Rapports and Menu buttons. The Menu offers the trial mode in games without an account, and a badge in the top bar shows it is on. Touching anything on a map opens its panel beside the map (`SidePanel`; `screen.ts` holds the `Panel` and `CitySelection` types):
      - a building: `BuildingCard`, plus `TrainingList` for the Caserne (the four family units and the player's race unit, as `UnitCard`s with a `CountPicker` slider), `ResearchPanel` and `TechCard` for the Académie, `SpellList` for the Tour des mages (the boons, then the defence spells « Pour tes absences »), `DefenseCard` for the Remparts (siege in progress, by one raid or several, with the armies helping from outside; the defence spells at work, and the next raid counted past the Brume d'oubli; guards, health bonus, troops at home, what the Château protects, raids on the way and the next one), `DragonCard` for the Aire du dragon (where to find the egg, hatching it, the hatching countdown, then the dragon's level, XP or the Aire holding it back, strength, upkeep, and where it is), `HospitalCard` for the Hôpital (beds taken, the healing in progress, and the wounded with a `CountPicker` each, all chosen at first, to heal them);
      - the garrison (`GarrisonCard`: troops at rest, the wounded at the Hôpital, upkeep, famine, dismissal) and the heroes (`HeroPanel`, `HeroCard`: recruit, XP, skill points), which both have a spot on the city map;
      - a camp, a band (or a raid: its arrival countdown and an "Intercepter" button) or a node: `TargetCard`, which composes a new army (hero chips, an "Emmener le dragon" chip, sliders; by default every troop, led by a free hero, a gatherer for a node and a fighter otherwise, and the dragon for a fight when it is home and fit) that leaves at once, or sends an army already outside, and warns about monsters near the route; for a band, whether it is fighting one of your armies (another army can strike it from the side or the rear), chasing one, or walking back; for the great encampment's bands it says what each one is (the tower's alarm included), that the trial needs several armies (or the trial mode), that traps are hidden, and when the encampment repopulates;
      - one of your armies: `ArmyCard` (status, the bands chasing it, its melee: the foe it strikes and from which side, who strikes it and from where, whether it is encircled; load, hero, and the key of the great encampment if it carries it). While an army is selected, a tap on the ground, a target or the city orders it there at once, with no button to validate: `command` checks with `checkOrder` and shows a refusal as a toast. Dragging an army to a place or a target does the same (`WorldMap` emits `command`). A fighting army only retreats through its button, so a stray tap cannot pull it out of a battle, but a tap on another foe of its melee turns it toward that foe;
      - pages: the objective (`QuestBanner`), battle reports (`ReportsPanel`, with the collapsible combat log; reports show the wounded among the losses, the hero's and the dragon's XP, a siege report its defenders, guards lost, and loot or plunder, and a trap report its losses) and the menu (account, fullscreen with a landscape lock where the browser allows it, restart).
      "Bon retour" is a dialog over the game. `world.ts` holds the `Selection` type, the French texts for orders and army statuses, band names (`bandName`), the bands chasing an army (`chasers`), the raids on the way (`incomingRaids`), the foe an army strikes (`armyFoeName`), and what animates a melee (`fightFx(battle, fighter)`: a fighter's health ratio and the damage it just took; `shot`: a spark's path); `battleLog.ts` holds the combat log's text and names foes (`foeName`, `foesName` for every foe of a report, `bandLabel`) and outcomes (`OUTCOME_NAMES`, and `reportTitle`, which names siege outcomes from the city's side, and a trap « Piège »).

- Maps are plain SVG, no library. `MapViewport.vue` fills its frame and handles panning and zooming (pointer events for drag and pinch, wheel, keyboard, on-screen buttons that `GameScreen` places through CSS variables); one can zoom out until the whole map shows. It renders its slot in world units. A tap only counts as a selection when the pointer did not drag; a tap on the background emits `tap` with the point in world units. It exposes `centerOn` (the maps center on each new selection, once the panel has opened, and also when a map first appears with a selection already made: a point asked for before the map has a size waits until it is framed) and `toWorld` (used to drag armies). `maps.ts` holds the city layout (building plots, the garrison and heroes spots, the wall, and `CITY_SIEGE`, where besiegers stand) and the deterministic decor; positions on the world map come from `config.ts`. `CityMap.vue` and `WorldMap.vue` draw the scenes; bands and armies move once a second, smoothed by a CSS transition (`.mover`). On the city map, the Aire du dragon shows the egg (wobbling, with a hatching bar) or the dragon when it is home (breathing, asleep under 💤 while it rests), and the wall is a palisade until the Remparts are built, then a stone wall that thickens with their level, ringed in red during a siege. On the world map, the mountain barrier is drawn as one rock mass (`.massif-edge` under `.massif`, so overlapping massifs show no seams) covered with peaks (`WORLD_DECOR.peaks`, placed where a massif holds them), around the encampment's cirque, its name on the ridge with the countdown to its repopulation, and its gate (🔒, or 🔓 once open); its chiefs carry a badge (`CHIEF_BADGES`: 🗝️ keeper, 🛡️ guard, 👑 warlord, 👁️ watchtower) and the army carrying the key a 🗝️; the tower's watch zone shows while it stands, and sprung traps show as 🪤 until the reset (unsprung ones stay hidden). Each band's circle (`.zone`, drawn in its own layer under the chase lines) is its sight for a patrol and its aggro zone for a chief or a raid; in the encampment the circles have no edge (`.faint`) unless the band is selected or near the route, because they all overlap. A chasing band carries a ❗ and a red line with flowing dashes (`.chase-line` over a dark `.chase-halo`) runs from it to its prey (`chases`); the route of the chosen army or target follows its detours (`routeLine`), straight and red when no route reaches it. A raid has no patrol loop but a red path to the city, and a raid at the gates is drawn in front of the city, on the side it came from (`drawnPosition`), so it never hides the city. An army with the dragon carries a 🐉 badge. In a melee each fighter is drawn at its slot around its target (`battleLayout`, `placed`, `SLOT_OFFSETS`: a little further above and below, for names and health bars; raids around the city at `CITY_SLOT_OFFSETS`); the foe that strikes back at an army, the city and waiting fighters stay where they are. A dashed line joins each striker to its target (`clashes`, one line for two fighters facing each other), and an encircled army's ring turns red and pulses (`.surrounded`).
- Battles are animated on both maps: a `HealthBar` above each side (gold for the player, red for monsters), the damage of each round floating up (`.float-damage`), a shake on whoever is hit (`.hit`), sparks flying between the fighters (`.spark`) and crossed swords that bump each round, with the round number in a badge. Elements keyed by the round number restart their CSS animation each round. During a siege, both bars (your defenders, all the raids together) and both damage numbers sit above the besiegers on the city map, whose label counts the raids.
- The maps have some life: `MapGround` draws the ground (terrain patches from `maps.ts` and a grass pattern); mountains have snow caps (`mountainSnow`) and, like trees, a shadow; roads have edges; water flows (`.river-light`, in steps to spare phones) and the lake shimmers; campfires flicker by the camps; marching armies and bands bob (`.walker`), gatherers swing their pickaxe, raids pulse; in the city, the hammer of a works hits, producing buildings release their resource now and then (`.puff`), the mana well glows, and the Caserne, Académie, Tour des mages and Hôpital show when they are busy. `MapViewport` adds drifting clouds and a vignette as HTML layers over the map, which cost little. The selected spot's ring breathes. A global `prefers-reduced-motion` rule in `style.css` stops all of it, keeps each round's damage numbers on screen (still), and hides sparks and clouds. Big pulses (the wall during a siege, a raid's zone) change in two steps (`steps(2)`), because repainting them every frame slowed modest phones down. Messages (`.hud-toasts`) sit at the bottom of the map, above the buttons, and the passing ones let taps through. When a siege starts, the city map turns to the south gate (`focusSiege`).
- Styling: a single dark theme defined as CSS custom properties in `src/style.css`, which also holds the shared card (`.plaque`), grid, progress and form styles; component styles are scoped. The game screen takes the full height (`html`, `body` and `#app` are 100 % high, with the phone's safe areas as padding on `:root`), while the account and race screens scroll. Lists of cards (`.grid`) follow the width of their panel through a container query. Icons are emoji placeholders set in `config.ts`. `docs/graphismes.md` holds the art style guide and the list of images (with file names) that will replace them.

## Game Design

Design decisions live in `docs/conception.md` (in French). It is the source of truth and supersedes the README where they differ. Read it before implementing gameplay, and update it whenever the owner settles a design question. Each item is tagged Décidé, Proposition or À trancher. Ideas not yet decided (from the November 2026 review by a team of agents: interface, mechanics, design, server) live in `docs/pistes.md`, each with an id the owner can pick, and leave it once decided.

In short: a free-for-everyone (no pay-to-win) multiplayer kingdom-building strategy game, in the same genre as Rise of Kingdoms but with a medieval-fantasy setting (several playable races, magic, dragons). Everything runs in real time with durations, combat included: there is no turn-based mode. Progress continues while the player is offline. All content (name, races, heroes, art) must be original; never reuse Rise of Kingdoms' content.

Platform roadmap: web app first, then packaged as an Android app via Ionic/Capacitor. Keep the web stack compatible with that (the Vite build already uses relative asset paths). The game is played in landscape: the Android app will lock that orientation (`android:screenOrientation="sensorLandscape"`).
